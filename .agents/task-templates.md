# task-templates.md

向 Agent 描述任务时的标准化模板。使用这些模板可以降低沟通成本，确保 Agent 准确理解你的意图。

---

## 1. Bug 修复 (BugFix)

```
【Bug 修复】

**问题描述**：
[具体描述 bug 现象，如：创建活动时开始时间校验未生效]

**复现步骤**：
1. [步骤1]
2. [步骤2]
3. [观察到的异常行为]

**预期行为**：
[描述正确的行为应该是什么]

**涉及文件**（如已知）：
- [文件路径]

**环境信息**（如相关）：
- Java 版本 / Spring Boot 版本 / 数据库版本
```

**Agent 需产出**：
- 根因分析
- 修复代码
- 对应的单元测试（覆盖 bug 场景）
- CR 自检

---

## 2. 新功能 (Feature)

```
【新功能】

**功能名称**：[如：活动评论模块]

**需求描述**：
- [功能点1：用户可以发表评论]
- [功能点2：活动创建者可以删除评论]
- [功能点3：评论列表支持分页]

**数据模型**（如已设计）：
- 评论表 (comment): id, activity_id, user_id, content, created_at

**API 端点**（如已设计）：
- POST /api/v1/activities/{id}/comments — 发表评论
- DELETE /api/v1/comments/{id} — 删除评论
- GET /api/v1/activities/{id}/comments — 评论列表

**前端需求**（如相关）：
- 评论列表需包含用户头像和昵称
- 支持分页加载
```

**Agent 需产出**：
- 按 `create-crud-module` Skill 的文件清单创建代码
- 完整的单元测试（正常 + 异常路径）
- 更新 `API-endpoints.md`
- CR 自检

---

## 3. 重构 (Refactor)

```
【重构】

**重构目标**：[如：将 ActivityService 中的权限校验逻辑抽取到独立的方法]

**现状问题**：
- [问题1：权限校验代码在多个方法中重复]
- [问题2：xxx 方法过长，难以测试]

**目标架构**：
[描述重构后的期望结构]

**约束条件**：
- [ ] 不改变现有 API 行为
- [ ] 已有单元测试必须继续通过
- [ ] 不引入新的依赖
```

**Agent 需产出**：
- 重构方案说明（改了什么、为什么这样改）
- 重构后的代码
- 运行已有测试确认无回归
- CR 自检

---

## 4. 性能优化 (Perf)

```
【性能优化】

**瓶颈描述**：[如：首页推荐活动查询耗时 > 2s]

**当前实现**：[简述当前实现方式]

**期望指标**：[如：优化后 < 200ms]

**可接受的方案**（如有限制）：
- [ ] 可以加缓存
- [ ] 可以加索引
- [ ] 不可以改表结构
```

## 5. 代码审查 (Review)

```
【代码审查】

**审查范围**：[分支名 / commit hash / 文件列表]

**审查重点**（可选）：
- [ ] 安全性
- [ ] 事务正确性
- [ ] API 设计
```

**Agent 需产出**：
- 按 `code-review.md` Skill 的检查清单输出审查报告
- 问题项标注严重程度和修复建议

---

## 通用规范（所有任务适用）

无论任务类型，Agent 都应遵循：

1. **任务拆分**：复杂任务先拆分为子任务，用 `- [ ]` 标记进度
2. **增量交付**：每完成一个子任务立即验证，不攒到最后
3. **测试先行**：涉及代码变更的任务，先写测试再写实现（或至少同步）
4. **CR 收尾**：每个会话结束前执行 Code Review
5. **文档更新**：有 API 变更时更新 `API-endpoints.md`，所有变更记录到 `CHANGELOG.md`
